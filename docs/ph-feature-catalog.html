What PH does
and how to use it

PH captures AI coding work, keeps the interaction archive on your machine by default, and gives you plain-text tools to find earlier prompts, responses, and durable project knowledge.

1. Product scope

PH is a local-first history and recall CLI for work with AI coding tools. It records completed exchanges, indexes prompt/response text, supports source-linked durable memories, and optionally connects clients to shared memory or raw-history services.

Coding tool→Local PH capture→SQLite + FTS5→Search / show / context

History

Prompt, captured response, tool, timestamp, working directory, exit status, and available metadata are stored in SQLite, normally ~/.prompt_history.db.

Durable memories

Small source-attributed facts or decisions are separate from full interactions. They can remain local or use the optional shared memory API.

Plain-text use

A bare ph prints a short guide. There is no interactive history browser or terminal UI.

Retrieval is explicit

PH does not inject project context into an agent automatically. Use ph context yourself or configure an agent to call PH's MCP tools.

2. Everyday workflow

npm install -g @gi4nks/ph
ph setup
# Restart the connected coding tools.
ph status

# Later, from a project directory:
ph search "sqlite migration"
ph show 42
ph context "add a memory search command"
ph memory search "migration"

ph setup is usually a one-time operation. Run the coding tools normally after their hooks or plugin are installed. Search is scoped to the current project when PH can identify it; use --all to search across projects.

3. Capture integrations and import

ph setup detects installed supported executables, installs or updates integration files, and preserves unrelated settings. Select tools explicitly with ph setup claude codex or ph setup agy; restart tools after setup reports a change. Hook scripts are copied beneath ~/.ph/hooks; the OpenCode plugin is installed beneath ~/.config/opencode/plugins.

Wrapper and manual capture

ph claude
ph codex --help
ph --ph-role review --ph-tag release claude
ph log --tool codex --prompt "Question" --response "Answer"
printf '%s' '{"tool":"codex","prompt":"Question","response":"Answer"}' | ph log

The wrapper forwards arguments to a tool on PATH. Interactive runs use a PTY; non-interactive runs infer the prompt from arguments and capture stdout as the response, so structured capture integrations are preferable when available. ph log accepts command flags or JSON on stdin.

OpenCode keeps the current pair in plugin memory until the next user message. If the session ends immediately after an answer, import the local OpenCode history later with ph import opencode --dry-run and backfill it without dry-run.

Import old local histories

ph import claude|codex|gemini|opencode|agy reads local tool data. Use --dry-run first; optional flags include --analyze, --filter, --file where supported, --workdir, and --live. Only --live runs configured post-capture processing for imported records.

Hooks, wrappers, explicit logging, and import all write local interaction history first. Remote transfer and LLM processing are separate, optional follow-up paths.

4. History, search, inspection, and export

Full-text search

SQLite FTS5 indexes prompts, responses, tool, and analysis text. Default search returns up to five results for the detected project; --all searches across projects.

Semantic search

ph search --semantic embeds the query with the configured Ollama embedding model and uses the vector index. Missing vectors, model mismatch, or provider failure falls back to text search.

Filters

Filter by tool, project, language, role, tag, starred state, quality, relevance, or date. --top means quality 8 or higher. --full prints complete prompt/response output.

Inspect and export

ph show <id> prints capture details and analysis; use --prompt or --full to reveal stored text. JSON and exports remain complete. Add --archive for archived rows.

ph search --project ph --tool codex "memory schema"
ph search --semantic "How did we fix database locking?"
ph show 42 --json
ph search --starred --since 2026-10-01 "release"
ph export 42 --format md

Other views include ph last, ph sessions, ph timeline, and ph stats. ph search --archive currently lists archived records by date and limit; it does not perform full-text query or normal metadata filtering on the archive.

5. Project context retrieval

ph context combines local project/work memories with relevant interactions for one project. If a hub is configured, it adds non-sensitive project/work memories from the hub. It never includes personal or sensitive memories in ordinary context.

ph context "how do database migrations work?"
ph context --project ph --memories-only
ph context --project ph --prompts-only
ph context --verbose --budget 6000 "search indexing"

Without a query, PH returns recent project memories and interactions. With a query, it uses FTS5 and fuses in semantic matches when an embedding index is available. If no interaction matches, it falls back to recent project interactions and notes that in the output. FTS5 retrieval works without an inference service. --limit controls result count; --budget bounds the formatted local context from 500 to 12,000 characters (default 3,500). Shared hub memories are appended outside that budget.

--verbose includes up to 1,000 characters from each selected prompt. It does not print the full prompt. Use ph show <id> --prompt or --full to reveal it.

6. Durable memories and shared hub

Memories are structured records with content, scope, kind, sensitivity, source/provenance, optional prompt references, status, and version history. They complement the transcript archive rather than replacing it.

DimensionValuesUse
Scopeproject, work, personalProject decisions, reusable work preferences, or personal facts.
Kinddecision, insight, preference, factLabels the type of durable knowledge.
Sensitivitynormal, sensitiveSensitive writes require an explicit user flag or API consent field.
StatusActive or reversibly forgottenForget/restore retains prior state in memory version history.
ph memory add --project ph --kind decision "Keep transcript history on this computer by default"
ph memory add --scope work --kind preference "Write user documentation in English"
ph memory search "migration" --project ph
ph memory forget 12
ph memory restore 12

Inside a detected project, new memories default to project scope; outside a project they default to work scope. When --prompts is supplied, PH validates each source against the local history before saving; project-scoped sources must belong to that project. Shared source references include the originating database identity and prompt ID. A shared hub routes new saves and memory list/search to the hub; context and MCP combine local and eligible shared records. For show/forget/restore, UUIDs address shared records and numeric IDs address local records. Local interaction history remains local unless raw-history sync is configured.

CLI, context, and MCP use the same MemoryService to select local or shared operations, validate source provenance, and fall back to local context when the hub is unavailable. Automatic extraction remains a separate hub-only worker.

Automatic extraction

When the shared hub URL/key are configured and memory-auto-capture is not false, supported completed coding-agent captures can schedule extraction. A configured inference provider is also required. PH asks for at most two work/project candidates, requires an exact quote from the user's prompt, rejects personal-scope and detected sensitive candidates, and stores provenance. It sends up to 4,000 prompt characters and 4,000 response characters to the configured inference provider; the hub receives derived memories and source references, not the transcript through this pathway.

ph status
ph memory retry 42
ph memory undo 42
ph config set memory-auto-capture false
Sensitive-data screening is imperfect. Configure extraction only when the selected inference service is appropriate for bounded prompt and response excerpts. Automatic extraction is separate from an agent's decision to call MCP.

9. MCP interface for coding agents

ph mcp starts a local stdio MCP server. Register it in an agent client, then reload the client and inspect its MCP status. These tools are available:

ToolWhat it does
search_historySearch interaction history with query and project/tool/date filters.
get_interactionReturn a complete interaction, including prompt, response, workdir, and analysis metadata.
get_project_contextRetrieve project interactions and eligible local/shared knowledge.
search_memoriesSearch project/work memories locally and at a configured hub.
save_memorySave project/work knowledge locally or at the configured hub, with optional prompt source validation.
# Claude Code
claude mcp add --transport stdio ph -- ph mcp

# Codex CLI
codex mcp add ph -- ph mcp

# Gemini CLI
gemini mcp add --scope user ph ph mcp

# OpenCode
opencode mcp add ph --global -- ph mcp

These registration examples follow the clients' documented CLI syntax; consult each client’s current MCP guide when its command changes. MCP does not itself extract memories from a conversation. PH capture-triggered extraction is a distinct background path. MCP currently does not expose personal/sensitive memory operations.

10. HTTP service and the two sync paths

Shared memory API

Configured PH clients can create, search, read, forget, and restore shared memory records. Memory records are stored in the service's SQLite database.

Raw history sync

Push/pull transfers prompt and response interactions between PH databases. Configuring the memory hub does not enable transcript sync.

ph config set memory-hub-url https://<private-host>
ph config set memory-hub-api-key

ph config set remote-url https://<private-sync-host>
ph config set remote-api-key
ph remote push
ph remote pull

PH_REMOTE_URL or remote-url enables automatic push after completed captures. Explicit ph remote push|pull uses resumable pages and per-database/per-target checkpoints. It can transfer full prompts and responses.

The HTTP service binds to 127.0.0.1:3001 by default. Direct ph server startup requires at least one credential: a history-service key or memory-hub key. A memory-only server needs only the memory key; prompt-history routes require the history-service key. When both keys are configured, they must differ. The included Docker Compose configuration currently also requires the history-service key. Only /health is public.

RoutesAuth / role
GET /healthPublic status-only check.
/api/memories...Memory-hub bearer key; CRUD/search and reversible forget/restore.
/api/prompts..., /api/sync..., /api/statsServer bearer key; prompt search/detail/semantic, raw sync, aggregate stats.

For generic self-hosted deployment, persistence, reverse-proxy guidance, environment files, and the memory API contract, use the Memory Hub operations guide.

12. Maintenance, safety, and current limits

History retention and deletion

  • ph cleanup --dry-run previews rule-based deletions; applying it without dry-run deletes matching active rows.
  • ph cleanup --days N deletes interactions older than N days and still runs rule-based cleanup.
  • ph cleanup --retention --dry-run previews archive candidates. Applying retention archives old rows and may purge archived rows older than twice the configured retention age.
  • ph vacuum compacts SQLite after substantial deletions. Back up the database before destructive maintenance.

Not implemented in the current product

  • No TUI or interactive history browser.
  • No automatic context injection into coding-agent prompts.
  • No email, calendar, browser, or personal-assistant connectors.
  • No per-client identity or connector-level authorization in the memory hub; clients share one memory bearer key.
  • No offline memory write queue or conflict-resolution workflow.
  • Memory hub search is SQLite FTS5; memory embeddings/indexing are not provided by the hub.
Inference and raw sync have different trust boundaries: analysis/extraction sends bounded content to a configured model provider; raw sync sends interaction records to the configured PH server. The shared-memory path sends derived records and provenance.
