Current posture

The product already has a coherent local-first core: capture conversations, attach project metadata, search them, derive summaries, then expose the result to people and agents. Its feature surface is broad; the next architectural gain comes from making retrieval behavior consistent and easy to evaluate.

Decision record · 2026-10-09

Chosen: treat `ph` as a local-first AI work memory and make shared project-context retrieval the first architectural move. Status: implemented for CLI, chat, and MCP; project-scoped semantic lookup now filters before the final result limit.

Why: a shared retrieval seam makes source selection consistent and creates a place to evaluate evidence ranking. The deterministic fixture currently reports Recall@2 = 1.0 and MRR = 1.0 on synthetic vectors; this does not measure real embedding relevance.

Not decided: hosted/team sync, a GUI beyond the existing TUI, and any replacement database. These need separate product decisions.

Cost, rate limits, and latency

Plain text search and local SQLite reads need no model call. Semantic context and MCP semantic search call the configured Ollama embedding endpoint; unavailable or slow Ollama can delay or fail those paths. Background analysis calls the selected Ollama or Gemini provider, so Gemini usage may incur provider cost and rate limits; enabling it makes each captured interaction eligible for asynchronous analysis. Keep these calls optional, expose failure/latency clearly, and avoid repeating embedding calls when an equivalent vector is already available.

Candidates for deepening

1. Shared project-context retrieval

Strong · P0

src/commands/context.ts:22-89 · src/commands/chat.ts:21-65 · src/mcp/server.ts:305-402

Problem. Consumers independently select memories/prompts, filter projects, and assemble Markdown. The chat path uses recent prompts while the MCP context path combines summary, memories, and interactions; output meaning can drift.

Solution. Deepen a context retrieval module behind a Seam that accepts project, query, limits, and source preferences, then returns structured evidence. Keep CLI, chat, and MCP as thin renderers/adapters.

2. PhDB capability boundary

Solution. After the context seam exists, identify the smallest storage capabilities needed by retrieval and sync. Extract only where a real consumer boundary becomes clearer; preserve SQLite as the default implementation.

4. Capture adapter contract and coverage

Worth exploring · P1

src/commands/log.ts · src/runner/{inline,project,git-context}.ts · src/pty/wrapper.ts · src/importer/*.ts · hooks/

Problem. Capture spans wrappers, shell hooks, a plugin, stdin logging, and importers. Their external payloads and pairing rules vary, while the test inventory is small relative to the integration surface.

Solution. Define and validate one normalized capture record at the ingestion boundary, then keep each provider-specific adapter responsible for parsing its source format. Add contract fixtures for adapters as they are actively supported.

Top recommendation

Delivered: shared project-context retrieval and focused verification.

CLI context, chat, and MCP share structured retrieval and Markdown formatting. Project filtering now happens before the result limit. The deterministic regression fixture reports Recall@2 = 1.0 and MRR = 1.0; the maintainer-judged model evaluation is runnable with npm run eval:retrieval and requires a reachable 768-dimensional Ollama embedding model.

Capture normalization, TUI filter policy, importer fixtures, MCP tool calls, and PTY response cleanup now have focused tests. Vector encoding, compatibility storage, and ranking now live in SemanticIndex while PhDB retains its public methods. Further splits wait for a second adapter or an independent migration seam.

What ph can do today

Capture and import

Wrap a CLI tool, accept direct `ph log` input, use Claude/Codex/Gemini hooks or the OpenCode plugin, and import histories from all four tools.

src/commands/{wrap,log,import}.ts · hooks/ · src/importer/

Search and browse

Use FTS and filters, semantic search when vectors exist, archive search, and the Ink TUI to inspect, star, edit, or rerun entries.

src/commands/search.ts · src/db/index.ts · src/ui/BrowseApp.tsx

Build project knowledge

Analyze captured interactions with Ollama or Gemini, accumulate summaries and decisions, view project timelines, and produce pipe-ready context.

src/analyzer/ · src/commands/{analyze,context,timeline}.ts · src/db/index.ts

Connect agents and machines

Expose MCP tools over stdio and run an optional HTTP API for prompt search and push/pull synchronization.

src/mcp/server.ts · src/server/index.ts · src/commands/remote.ts

Ready for...

Personal local prompt history, manual retrieval, agent queries through MCP, and optional single-user machine sync, provided the configured local database and embedding/analysis services are available for the selected features.

Still requires integration...

Reliable out-of-the-box cross-tool capture, consistent context quality across consumers, and shared/team hosted memory. Specifications establish a broad implemented baseline, but not product-level evidence for every external tool version or operational deployment.
